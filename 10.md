# Mount AWS S3 Bucket as a Filesystem (Ubuntu, s3fs-fuse)

Bucket used in this example: `qt-devops-s3` (region: `eu-north-1`)

S3 is object storage, not a real filesystem. `s3fs-fuse` provides a FUSE-based
overlay that lets you mount a bucket as a local directory. It is not a true
block-level mount — expect higher latency and partial POSIX compliance (no
real file locking, unusual `rename`/`append` behavior).

## 1. Install s3fs

```bash
sudo apt update
sudo apt install s3fs -y
s3fs --version
```

## 2. Set up authentication

### Option A — IAM Role (recommended, no keys on disk)

Attach an IAM role to the EC2 instance with a policy like:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket",
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": [
        "arn:aws:s3:::qt-devops-s3",
        "arn:aws:s3:::qt-devops-s3/*"
      ]
    }
  ]
}
```

Attach via **EC2 Console → Instance → Actions → Security → Modify IAM role**.

### Option B — Static access keys

```bash
echo "ACCESS_KEY_ID:SECRET_ACCESS_KEY" > ~/.passwd-s3fs
chmod 600 ~/.passwd-s3fs
```

## 3. Enable `allow_other`

Required if other users/processes need access to the mount, or if you hit:

```
fusermount: option allow_other only allowed if 'user_allow_other' is set in /etc/fuse.conf
```

Fix:

```bash
echo "user_allow_other" | sudo tee -a /etc/fuse.conf
grep user_allow_other /etc/fuse.conf
```

No reboot required — read at mount time.

## 4. Create the mount point

```bash
sudo mkdir -p /mnt/qt-devops-s3
sudo chown ubuntu:ubuntu /mnt/qt-devops-s3
```

## 5. Mount the bucket

**With IAM role:**

```bash
s3fs qt-devops-s3 /mnt/qt-devops-s3 \
  -o iam_role=auto \
  -o url=https://s3.eu-north-1.amazonaws.com \
  -o endpoint=eu-north-1 \
  -o use_path_request_style \
  -o allow_other
```

**With static keys:**

```bash
s3fs qt-devops-s3 /mnt/qt-devops-s3 \
  -o passwd_file=${HOME}/.passwd-s3fs \
  -o url=https://s3.eu-north-1.amazonaws.com \
  -o endpoint=eu-north-1 \
  -o use_path_request_style \
  -o allow_other
```

> Newer-style regions (e.g. `eu-north-1`) require **both** `url` and
> `endpoint` — otherwise s3fs defaults to `us-east-1` signing and returns
> `403 Forbidden`.

## 6. Verify

```bash
df -h | grep qt-devops-s3
ls /mnt/qt-devops-s3
```

## 7. Unmount

```bash
sudo umount /mnt/qt-devops-s3
```

## 8. Persist across reboots (`/etc/fstab`)

**IAM role:**

```
qt-devops-s3 /mnt/qt-devops-s3 fuse.s3fs _netdev,allow_other,iam_role=auto,url=https://s3.eu-north-1.amazonaws.com,endpoint=eu-north-1 0 0
```

**Static keys:**

```
qt-devops-s3 /mnt/qt-devops-s3 fuse.s3fs _netdev,allow_other,passwd_file=/home/ubuntu/.passwd-s3fs,url=https://s3.eu-north-1.amazonaws.com,endpoint=eu-north-1 0 0
```

Test without rebooting:

```bash
sudo mount -a
```

## Troubleshooting

| Issue | Fix |
|---|---|
| `fuse: device not found` | `sudo apt install fuse`; add user to `fuse` group |
| `allow_other` error | Set `user_allow_other` in `/etc/fuse.conf` (Step 3) |
| `403 Forbidden` in newer regions | Set both `url` and `endpoint` options |
| Slow directory listing on large buckets | Add `-o stat_cache_expire=300 -o enable_noobj_cache` |
| IMDSv2 metadata errors with `iam_role=auto` | Ensure `s3fs >= 1.86` |

## When not to use S3-FUSE

For production workloads that need real POSIX filesystem semantics (locking,
atomic writes, high IOPS), use **Amazon EFS** or **FSx** instead. S3-FUSE
mounts are a workaround for object storage, not a substitute for a real
filesystem.
