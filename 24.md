# AWS Databases (Non-RDS): Create Data, Insert Data, Get Data

Each example uses the same student data so you can compare how every database stores and reads it:

| id | name | course |
|---|---|---|
| S001 | Ravi | DevOps |
| S002 | Sita | AWS |

---

## 1. DynamoDB

**Create the table** (console: DynamoDB, Create table, name `Students`, partition key `StudentId` String) or with CLI:

```bash
aws dynamodb create-table \
  --table-name Students \
  --attribute-definitions AttributeName=StudentId,AttributeType=S \
  --key-schema AttributeName=StudentId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
```

**Insert data**

```bash
aws dynamodb put-item --table-name Students \
  --item '{"StudentId":{"S":"S001"},"Name":{"S":"Ravi"},"Course":{"S":"DevOps"}}'

aws dynamodb put-item --table-name Students \
  --item '{"StudentId":{"S":"S002"},"Name":{"S":"Sita"},"Course":{"S":"AWS"}}'
```

**Get data**

```bash
# One item by key
aws dynamodb get-item --table-name Students \
  --key '{"StudentId":{"S":"S001"}}'

# All items
aws dynamodb scan --table-name Students

# Filter
aws dynamodb scan --table-name Students \
  --filter-expression "Course = :c" \
  --expression-attribute-values '{":c":{"S":"AWS"}}'
```

**Update and delete**

```bash
aws dynamodb update-item --table-name Students \
  --key '{"StudentId":{"S":"S001"}}' \
  --update-expression "SET Course = :c" \
  --expression-attribute-values '{":c":{"S":"DevOps and Docker"}}'

aws dynamodb delete-item --table-name Students \
  --key '{"StudentId":{"S":"S002"}}'
```

## 2. ElastiCache (Redis OSS / Valkey)

Connect from EC2 in the same VPC: `redis-cli -h <endpoint> -p 6379`

**Insert data**

```
SET student:S001 "Ravi"
HSET student:S002 name "Sita" course "AWS"
```

**Get data**

```
GET student:S001
HGET student:S002 name
HGETALL student:S002
```

**Cache with expiry (typical caching use)**

```
SET session:1001 "ravi" EX 300
TTL session:1001
```

**Delete**

```
DEL student:S001
```

## 3. MemoryDB

Connect with TLS: `redis-cli --tls -h <endpoint> -p 6379`

The commands are the same as Redis. Data survives node failures because MemoryDB stores writes durably.

**Insert data**

```
HSET student:S001 name "Ravi" course "DevOps"
HSET student:S002 name "Sita" course "AWS"
```

**Get data**

```
HGETALL student:S001
HGET student:S002 course
KEYS student:*
```

## 4. DocumentDB (MongoDB compatible)

Connect:

```bash
mongosh --tls --host <cluster-endpoint>:27017 \
  --tlsCAFile global-bundle.pem --username adminuser --password
```

**Create database and collection** (created automatically on first insert)

```javascript
use school
db.createCollection("students")
```

**Insert data**

```javascript
db.students.insertOne({ _id: "S001", name: "Ravi", course: "DevOps" })

db.students.insertMany([
  { _id: "S002", name: "Sita", course: "AWS" },
  { _id: "S003", name: "Arjun", course: "DevOps" }
])
```

**Get data**

```javascript
db.students.find()
db.students.find({ course: "DevOps" })
db.students.findOne({ _id: "S002" })
```

**Update and delete**

```javascript
db.students.updateOne({ _id: "S001" }, { $set: { course: "DevOps and Docker" } })
db.students.deleteOne({ _id: "S003" })
```

## 5. Neptune (Graph, openCypher)

Send queries over HTTPS from inside the VPC:

```bash
curl -X POST https://<cluster-endpoint>:8182/openCypher \
  -d 'query=<your query>'
```

**Insert data** (nodes and a relationship)

```cypher
CREATE (:Student {id: 'S001', name: 'Ravi'})
CREATE (:Student {id: 'S002', name: 'Sita'})
CREATE (:Course {name: 'DevOps'})
```

```cypher
MATCH (s:Student {id: 'S001'}), (c:Course {name: 'DevOps'})
CREATE (s)-[:ENROLLED_IN]->(c)
```

**Get data**

```cypher
// All students
MATCH (s:Student) RETURN s.id, s.name

// Who is enrolled in DevOps
MATCH (s:Student)-[:ENROLLED_IN]->(c:Course {name: 'DevOps'})
RETURN s.name
```

## 6. Keyspaces (CQL)

Run these in the console **CQL editor** or with `cqlsh`.

**Create keyspace and table**

```sql
CREATE KEYSPACE school
WITH replication = {'class': 'SingleRegionStrategy'};

CREATE TABLE school.students (
  id text PRIMARY KEY,
  name text,
  course text
);
```

**Insert data**

```sql
INSERT INTO school.students (id, name, course) VALUES ('S001', 'Ravi', 'DevOps');
INSERT INTO school.students (id, name, course) VALUES ('S002', 'Sita', 'AWS');
```

**Get data**

```sql
SELECT * FROM school.students;
SELECT name, course FROM school.students WHERE id = 'S001';
```

**Update and delete**

```sql
UPDATE school.students SET course = 'DevOps and Docker' WHERE id = 'S001';
DELETE FROM school.students WHERE id = 'S002';
```

## 7. Redshift (SQL)

Run in **Query editor v2**.

**Create table**

```sql
CREATE TABLE students (
  id     VARCHAR(10),
  name   VARCHAR(50),
  course VARCHAR(50)
);
```

**Insert data**

```sql
INSERT INTO students VALUES ('S001', 'Ravi', 'DevOps');
INSERT INTO students VALUES ('S002', 'Sita', 'AWS');
```

**Load many rows from S3** (the normal way in Redshift)

```sql
COPY students
FROM 's3://my-bucket/students.csv'
IAM_ROLE 'arn:aws:iam::123456789012:role/RedshiftS3Role'
CSV IGNOREHEADER 1;
```

**Get data**

```sql
SELECT * FROM students;
SELECT course, COUNT(*) AS total FROM students GROUP BY course;
```

> Row-by-row `INSERT` is slow in Redshift. Use `COPY` for bulk loads.

## 8. OpenSearch Service

Run in **Dashboards, Dev Tools**.

**Create index**

```
PUT students
{
  "mappings": {
    "properties": {
      "name":   { "type": "text" },
      "course": { "type": "keyword" }
    }
  }
}
```

**Insert data**

```
PUT students/_doc/S001
{ "name": "Ravi", "course": "DevOps" }

PUT students/_doc/S002
{ "name": "Sita", "course": "AWS" }
```

**Get data**

```
# One document by id
GET students/_doc/S001

# All documents
GET students/_search
{ "query": { "match_all": {} } }

# Search
GET students/_search
{ "query": { "match": { "name": "Ravi" } } }

# Filter by course
GET students/_search
{ "query": { "term": { "course": "AWS" } } }
```

## 9. Timestream for InfluxDB

Use the **InfluxDB UI** (Data Explorer / Load Data) or the `influx` CLI.

**Insert data** (line protocol: measurement, tags, fields)

```bash
influx write --bucket metrics --org myorg --token <token> \
  'cpu,host=server1 usage=42.5
cpu,host=server2 usage=71.2'
```

**Get data** (Flux query)

```
from(bucket: "metrics")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "cpu")
  |> filter(fn: (r) => r.host == "server1")
```

## Quick Comparison

| Database | Create structure | Insert | Get |
|---|---|---|---|
| DynamoDB | `create-table` | `put-item` | `get-item`, `scan` |
| ElastiCache / MemoryDB | none (keys on the fly) | `SET`, `HSET` | `GET`, `HGETALL` |
| DocumentDB | `createCollection` | `insertOne` | `find` |
| Neptune | none (schema-less) | `CREATE (...)` | `MATCH ... RETURN` |
| Keyspaces | `CREATE TABLE` | `INSERT INTO` | `SELECT` |
| Redshift | `CREATE TABLE` | `INSERT`, `COPY` | `SELECT` |
| OpenSearch | `PUT index` | `PUT index/_doc/id` | `GET`, `_search` |
| InfluxDB | bucket | line protocol | Flux `from(...)` |
