# Backup in AWS and Azure

## What is Backup?

Backup is the process of creating copies of data, applications, and system configurations so they can be restored after data loss, corruption, accidental deletion, ransomware, or a disaster. A good backup strategy answers three questions:

- **RPO (Recovery Point Objective)** — how much data can you afford to lose (e.g., 1 hour, 1 day)?
- **RTO (Recovery Time Objective)** — how fast must you be back up and running?
- **Retention** — how long must copies be kept (compliance, legal, operational needs)?

The industry standard rule of thumb is the **3-2-1 rule**:
- **3** copies of data
- **2** different storage media/types
- **1** copy off-site (or in a different region/account)

## Backup in AWS

### 1. AWS Backup (centralized service)
A managed service that lets you create backup policies ("backup plans") and apply them across many AWS services from one place, instead of configuring backups per-service.

Supports:
- Amazon EBS (volumes)
- Amazon EC2 (whole instances)
- Amazon RDS / Aurora (databases)
- Amazon DynamoDB
- Amazon EFS / FSx (file systems)
- Amazon S3 (since 2023)
- AWS Storage Gateway

Key features:
- **Backup plans**: schedule (e.g., daily/weekly), lifecycle rules (move to cold storage, expire after X days), and retention.
- **Backup vaults**: encrypted containers that store recovery points; can be locked (WORM) with **Vault Lock** for compliance/ransomware protection.
- **Cross-region and cross-account copy**: automatically copy backups to another AWS region or account for disaster recovery and isolation from a compromised account.
- **On-demand and scheduled backups**.
- **Tag-based backup selection**: automatically back up resources based on tags.

### 2. Service-native backup options
Even without AWS Backup, most services have their own mechanisms:

| Service | Native Backup Method |
|---|---|
| EBS | Point-in-time **snapshots**, incremental after the first |
| EC2 | **AMI (Amazon Machine Image)** — full instance image |
| S3 | **Versioning** + **Cross-Region Replication (CRR)** + lifecycle rules to Glacier |
| RDS/Aurora | Automated daily snapshots + manual snapshots + point-in-time recovery (PITR) |
| DynamoDB | On-demand backups + **Point-in-Time Recovery** (continuous, up to 35 days) |
| EFS | Automatic backups via AWS Backup |

### 3. Long-term/cold storage
- **S3 Glacier / Glacier Deep Archive** — very low-cost storage for long-term backup retention (minutes to hours retrieval time).
- **Lifecycle policies** automatically transition older backups from S3 Standard → Infrequent Access → Glacier → Deep Archive.

### 4. Disaster Recovery add-ons
- **AWS Elastic Disaster Recovery (DRS)** — continuous block-level replication of on-prem or cloud servers to AWS for fast failover (near-zero RPO).

## Backup in Azure

### 1. Azure Backup (centralized service)
Azure's equivalent managed backup service — one control plane to protect Azure and on-premises workloads.

Supports:
- Azure VMs
- Azure Files (file shares)
- Azure Blobs (operational backup + vaulted backup)
- Azure SQL / SQL Server on VMs
- Azure Database for PostgreSQL/MySQL
- SAP HANA
- On-premises servers (via the **MARS agent** or **Azure Backup Server**)

Key concepts:
- **Recovery Services Vault**: the storage entity that holds backup data (similar to an AWS Backup vault).
- **Backup policies**: define schedule, retention (daily/weekly/monthly/yearly), and frequency.
- **Soft delete**: deleted backup data is retained for a grace period (protects against accidental/malicious deletion).
- **Immutable vaults**: WORM-style protection, similar to AWS Vault Lock, for ransomware resilience.
- **Cross-region restore**: restore VM backups into a secondary (paired) Azure region.
- **Geo-redundant storage (GRS)** option for the vault itself, so backup data is replicated to a paired region automatically.

### 2. Service-native backup options

| Service | Native Backup Method |
|---|---|
| Azure Managed Disks | **Snapshots** (incremental snapshots supported) |
| Azure VM | Full VM backup via Recovery Services Vault |
| Azure SQL Database | Automatic backups (full + differential + log), **Point-in-Time Restore** |
| Azure Blob Storage | **Versioning**, **Soft delete**, **Point-in-time restore for block blobs** |
| Azure Files | Native share snapshots + Azure Backup integration |

### 3. Long-term/cold storage
- **Azure Blob Storage tiers**: Hot → Cool → Cold → **Archive** (lowest cost, hours-long rehydration).
- Lifecycle management policies move backup data between tiers automatically based on age.

### 4. Disaster Recovery add-ons
- **Azure Site Recovery (ASR)** — replicates entire VMs/workloads (Azure-to-Azure, on-prem-to-Azure, VMware/Hyper-V-to-Azure) for near-continuous replication and orchestrated failover — Azure's counterpart to AWS DRS.

## AWS vs Azure — Quick Comparison

| Concept | AWS | Azure |
|---|---|---|
| Centralized backup service | AWS Backup | Azure Backup |
| Storage container | Backup Vault | Recovery Services Vault |
| Immutability/WORM | Vault Lock | Immutable Vault |
| Disk snapshot | EBS Snapshot | Managed Disk Snapshot |
| VM image | AMI | VM Backup / Managed Image |
| Cold archive tier | S3 Glacier / Deep Archive | Blob Archive Tier |
| DR replication service | AWS Elastic Disaster Recovery (DRS) | Azure Site Recovery (ASR) |
| Database PITR | RDS/Aurora automated backups | Azure SQL PITR |
| Accidental-deletion protection | S3 Versioning, DynamoDB PITR | Blob Soft Delete, Vault Soft Delete |

## Best Practices (applies to both clouds)

1. **Automate** backups with policies — don't rely on manual snapshots.
2. **Test restores regularly** — a backup you've never restored is not a verified backup.
3. **Encrypt backups** at rest (both AWS Backup and Azure Backup encrypt by default, using KMS/Key Vault keys).
4. **Isolate backups** — replicate to another region and ideally another account/subscription so a compromised primary environment can't destroy your backups too (ransomware protection).
5. **Enable immutability/WORM** (Vault Lock / Immutable Vault) for critical/compliance data so backups can't be deleted or altered even by an admin.
6. **Apply lifecycle tiering** to control cost — move older recovery points to cold/archive storage.
7. **Tag and classify resources** so backup policies apply automatically to new resources.
8. **Monitor and alert** on backup job failures (AWS Backup Audit Manager / CloudWatch; Azure Backup reports / Azure Monitor alerts).
9. **Document RPO/RTO per workload** — not everything needs the same backup frequency or retention.
