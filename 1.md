# Cloud Storage:

**Cloud storage** is a service where data is stored on remote servers (owned/managed by a cloud provider like AWS or Azure) and accessed over the internet, instead of being stored on a local disk or on-premises server.

Instead of buying and maintaining physical hard disks, you "rent" storage capacity from the cloud provider and pay only for what you use.

### Key Benefits

| Benefit | What it Means |
|---|---|
| **Scalability** | Expand or shrink storage anytime, without buying new hardware |
| **High Availability** | Data is accessible almost all the time, backed by redundant infrastructure |
| **Pay-as-you-go Pricing** | You pay only for the storage/IOPS/throughput you actually consume |
| **Backup & Disaster Recovery** | Built-in tools to replicate and restore data if something fails |

## Storage Terms — Quick Glossary

| Term | Meaning |
|---|---|
| **Backup (daily/hourly)** | Scheduled copies of data taken at fixed intervals; typically **5–10 snapshots** are retained at a time (older ones are rotated out) |
| **Archive** | Long-term, low-cost storage for data that is rarely accessed but must be retained |
| **HDD** | Hard Disk Drive — mechanical, cheaper, slower |
| **SSD** | Solid State Drive — faster, more expensive than HDD |
| **SSD Premium** | High-performance SSD tier for demanding, low-latency workloads (e.g., production databases) |
| **IOPS** | **I**nput/**O**utput **O**perations **P**er **S**econd — how many read/write operations a disk can handle per second (performance metric for random access) |
| **Throughput** | The rate of data transfer (e.g., MB/s) — how much data moves per second (performance metric for sequential/bulk transfer) |
| **Object Storage** | Storage for unstructured data as "objects" (data + metadata + unique ID), accessed via HTTP/HTTPS |
| **Cold Storage** | Storage tier optimized for infrequently accessed data, at lower cost but higher retrieval time/cost |

> **IOPS vs Throughput — quick way to remember:**
> IOPS = *how many* operations per second (good for small, random reads/writes — e.g., databases).
> Throughput = *how much data* moves per second (good for large, sequential transfers — e.g., video streaming, backups).

## Storage Units

### Decimal (Base 1000) — used by storage vendors for marketing/capacity

| Unit | Equals |
|---|---|
| KB | 1000 Bytes |
| MB | 1000 KB |
| GB | 1000 MB |
| TB | 1000 GB |

### Binary (Base 1024) — used by operating systems for actual memory addressing

| Unit | Equals |
|---|---|
| KiB | 1024 Bytes |
| MiB | 1024 KiB |
| GiB | 1024 MiB |
| TiB | 1024 GiB |

> **Why it matters:** This is why a "1 TB" hard disk shows up as roughly "931 GiB" in your OS — the vendor uses decimal (base 1000), while the OS uses binary (base 1024).

## Types of Storage

### Object Storage
Used for **unstructured data** — images, videos, backups, logs.

| | AWS | Azure |
|---|---|---|
| Service | S3 | Blob Storage |

**Features:**
- Stores data as objects (data + metadata + unique ID)
- Highly scalable
- Accessible via HTTP/HTTPS

**Use Cases:** Image storage, backups, static websites

### Block Storage
Used for **virtual machines and databases** — behaves like a raw disk attached to a VM.

| | AWS | Azure |
|---|---|---|
| Service | EBS | Managed Disks |

**Features:**
- Low latency
- High performance
- Attached to VMs like a hard disk

**Use Cases:** OS disks, databases

### File Storage
Used for **shared file systems** accessible by multiple machines at once.

| | AWS | Azure |
|---|---|---|
| Service | EFS | Azure Files |

**Features:**
- Supports SMB/NFS protocols
- Multiple systems can access the same storage simultaneously

**Use Cases:** Shared folders, lift-and-shift applications

### Object vs Block vs File — At a Glance

| Type | Best For | AWS | Azure | Access Style |
|---|---|---|---|---|
| Object | Unstructured data (media, backups, logs) | S3 | Blob Storage | HTTP/HTTPS API |
| Block | VMs, databases | EBS | Managed Disks | Attached disk (low latency) |
| File | Shared file systems | EFS | Azure Files | SMB/NFS |

## 3. Storage Classes / Tiers

Storage tiers let you balance **cost vs. access speed** based on how often data is used.

### AWS S3 Storage Classes
| Class | Purpose |
|---|---|
| Standard | Frequent access |
| Intelligent-Tiering | Auto-optimizes cost based on access patterns |
| Standard-IA | Infrequent access |
| Glacier | Archive |
| Glacier Deep Archive | Long-term storage (cheapest, slowest retrieval) |

### Azure Blob Storage Tiers
| Tier | Purpose |
|---|---|
| Hot | Frequent access |
| Cool | Less frequent access |
| Archive | Long-term storage |

> **Pattern to notice:** Both AWS and Azure follow the same logic — Frequent access (Standard/Hot) → Infrequent access (Standard-IA/Cool) → Archive (Glacier/Archive) — just with different names.

## 4. Data Redundancy

Redundancy = keeping multiple copies of data to protect against hardware failure or regional outages.

### AWS
- Multi-AZ replication (data copied across Availability Zones)
- **99.999999999% durability** (11 nines)

### Azure
| Type | Meaning |
|---|---|
| **LRS** | Locally Redundant Storage — copies within a single datacenter |
| **ZRS** | Zone Redundant Storage — copies across availability zones in a region |
| **GRS** | Geo Redundant Storage — copies replicated to a secondary, distant region |

> Redundancy generally scales with cost: LRS (cheapest, least protection) → ZRS → GRS (most protection, higher cost).

## 5. Security

### Common Features (Both Platforms)
- Encryption at rest (data encrypted while stored)
- Encryption in transit (data encrypted while moving over the network)
- Access control (who can read/write what)

### AWS
- **IAM policies** — define permissions for users/roles/services

### Azure
- **RBAC** (Role-Based Access Control) — assigns permissions based on roles
- **SAS tokens** (Shared Access Signatures) — time-limited, scoped access URLs to storage resources
