# Azure Queue Storage & Table Storage

## Overview

| Service | Data Model | Purpose |
|---|---|---|
| **Queue Storage** | Simple messages (up to 64 KB each) in a FIFO-ish queue | Decoupling app components, async task processing |
| **Table Storage** | NoSQL key-value store (PartitionKey + RowKey + properties) | Fast lookups on semi-structured, schemaless data |

Both live inside the same **Storage account** used for Blob Storage.

---

## Azure Queue Storage

### Create a Queue (Azure Portal)

1. Go to your **Storage account** in the [Azure Portal](https://portal.azure.com).
2. In the left menu, select **Queues** (under Data storage).
3. Click **+ Queue**.
4. Enter a **Name** (lowercase letters, numbers, hyphens only).
5. Click **OK**.

### Create a Queue (Azure CLI)

```bash
az storage queue create \
  --account-name mystorageacct123 \
  --name myqueue \
  --auth-mode login
```

### Upload (Enqueue) Sample Messages

```bash
az storage message put \
  --account-name mystorageacct123 \
  --queue-name myqueue \
  --content "order-1001: process payment" \
  --auth-mode login

az storage message put \
  --account-name mystorageacct123 \
  --queue-name myqueue \
  --content "order-1002: send confirmation email" \
  --auth-mode login
```

### Query (Peek/Read) Messages

```bash
# Peek at messages without removing them from the queue
az storage message peek \
  --account-name mystorageacct123 \
  --queue-name myqueue \
  --num-messages 5 \
  --auth-mode login

# Get (dequeue) messages — makes them invisible for a visibility timeout
az storage message get \
  --account-name mystorageacct123 \
  --queue-name myqueue \
  --num-messages 5 \
  --auth-mode login
```

### Delete a Processed Message

```bash
az storage message delete \
  --account-name mystorageacct123 \
  --queue-name myqueue \
  --id <message-id> \
  --pop-receipt <pop-receipt> \
  --auth-mode login
```

`<message-id>` and `<pop-receipt>` come from the output of `az storage message get`.

## Azure Table Storage

### Create a Table (Azure Portal)

1. Go to your **Storage account**.
2. In the left menu, select **Tables** (under Data storage).
3. Click **+ Table**.
4. Enter a **Table name**.
5. Click **OK**.

### Create a Table (Azure CLI)

```bash
az storage table create \
  --account-name mystorageacct123 \
  --name mytable \
  --auth-mode login
```

### Upload Sample Data (Insert Entities)

```bash
az storage entity insert \
  --account-name mystorageacct123 \
  --table-name mytable \
  --entity PartitionKey=orders RowKey=1001 CustomerName=Ravi Amount=250 Status=Pending \
  --auth-mode login

az storage entity insert \
  --account-name mystorageacct123 \
  --table-name mytable \
  --entity PartitionKey=orders RowKey=1002 CustomerName=Priya Amount=75 Status=Shipped \
  --auth-mode login
```

### Query Data

```bash
# Get a specific entity by PartitionKey + RowKey
az storage entity show \
  --account-name mystorageacct123 \
  --table-name mytable \
  --partition-key orders \
  --row-key 1001 \
  --auth-mode login

# Query with a filter
az storage entity query \
  --account-name mystorageacct123 \
  --table-name mytable \
  --filter "PartitionKey eq 'orders' and Status eq 'Pending'" \
  --auth-mode login

# List all entities in the table
az storage entity query \
  --account-name mystorageacct123 \
  --table-name mytable \
  --auth-mode login
```

### Update or Delete an Entity

```bash
# Merge (partial update)
az storage entity merge \
  --account-name mystorageacct123 \
  --table-name mytable \
  --entity PartitionKey=orders RowKey=1001 Status=Shipped \
  --auth-mode login

# Delete
az storage entity delete \
  --account-name mystorageacct123 \
  --table-name mytable \
  --partition-key orders \
  --row-key 1001 \
  --auth-mode login
```

---

## Notes

- Queue message content should be UTF-8 or Base64-encoded; max message size is 64 KB.
- Table Storage requires every entity to have a **PartitionKey** and **RowKey** — together they form the unique identifier.
- Filter syntax for `az storage entity query` follows OData conventions (`eq`, `ne`, `gt`, `lt`, `and`, `or`).
- For heavier querying/joins, consider **Azure Cosmos DB (Table API)** instead — it's wire-compatible with Table Storage but adds indexing and global distribution.
