## AWS Storage Redundancy — Step by Step

AWS Storage redundancy defines **how your data is replicated** to guarantee durability and availability.

### Step 1 — S3 One Zone-IA (lowest redundancy)
- Stores **3 copies**, but all within a **single Availability Zone (AZ)**
- Protects against hardware failure only
- ❌ Does **not** protect against an entire 
### Step 2 — S3 Standard (the default)
- Replicates across **3+ AZs** in the same region automatically
- **99.999999999%** (11 nines) durability
- ✔ Protects against AZ failure
- **Use case:** general-purpose storage — default for most workloads

### Step 3 — S3 Cross-Region Replication (CRR)
- Asynchronously copies objects to a bucket in a **different region**
- Replica is readable via its own endpoint
- Must be configured manually; adds replication cost
- **Use case:** disaster recovery across regions

### Step 4 — S3 Standard + CRR (Multi-region)
- Combines Step 2 (multi-AZ) **+** Step 3 (cross-region)
- Full geo-redundancy: high availability **and** disaster protection
- **Use case:** mission-critical applications

```
 One Zone-IA        Standard             Standard + CRR
┌──────────┐      ┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│  AZ-1    │      │  AZ-1  AZ-2   │    │ Region A       │───▶│ Region B      │
│ 3 copies │      │  AZ-3 (3+ AZ) │    │ (3+ AZ copies) │    │ (CRR replica) │
└──────────┘      └───────────────┘    └───────────────┘    └───────────────┘
  ❌ AZ fail          ✔ AZ fail            ✔ AZ fail  +  ✔ Region fail
```

### Redundancy Comparison Table

| Type | Copies | Scope | AZ Protection | Region Protection |
|---|---|---|---|---|
| S3 One Zone-IA | 3 | Single AZ | ❌ | ❌ |
| S3 Standard | ≥3 | Multiple AZs | ✔ | ❌ |
| S3 + CRR | ≥6 | Multi-region | ✔ | ✔ |
| EBS (single) | Multiple | Intra-AZ | ❌ | ❌ |

> Choose redundancy based on **cost vs. availability vs. disaster-recovery needs.**

## 3. S3 Storage Classes (Access Tiers) — Step by Step

S3 offers multiple **storage classes** to optimize cost based on *how often* data is accessed. Think of this as a ladder — the less frequently data is touched, the cheaper (but slower/costlier-to-retrieve) the tier.

```
Frequent access ────────────────────────────────────► Rarely accessed
   │                                                          │
Standard → Intelligent-Tiering → Standard-IA → One Zone-IA → Glacier Instant
   → Glacier Flexible → Glacier Deep Archive
   │                                                          │
Highest storage cost                              Lowest storage cost
Fastest retrieval                                 Slowest retrieval
```

### Step 1 — S3 Standard
- Frequently accessed data; highest storage cost; **no retrieval fee**; instant access
- **Use cases:** active datasets, website content, frequently used files

### Step 2 — S3 Intelligent-Tiering
- **Automatically** moves objects between frequent/infrequent tiers
- No retrieval fee, small per-object monitoring fee; instant access
- **Use cases:** unpredictable access patterns; avoid managing lifecycle rules manually

### Step 3 — S3 Standard-IA (Infrequent Access)
- Lower storage cost than Standard; **per-GB retrieval fee**; min. 30-day storage charge; instant access
- **Use cases:** short-term backups, DR data, ~monthly access

### Step 4 — S3 One Zone-IA
- Same as Standard-IA but in a **single AZ only**; ~20% cheaper; no AZ-failure protection
- **Use cases:** re-creatable infrequent data, secondary backup copies

### Step 5 — S3 Glacier Instant Retrieval
- Archive pricing with **millisecond** retrieval; higher retrieval fee; min. 90-day storage charge
- **Use cases:** ~quarterly access — medical images, news media archives

### Step 6 — S3 Glacier Flexible Retrieval
- Low-cost archive; retrieval in **1–12 hours** (expedited 1–5 min / standard 3–5 hrs / bulk 5–12 hrs); min. 90-day charge
- **Use cases:** compliance/archival data, ~yearly access

### Step 7 — S3 Glacier Deep Archive
- **Lowest** cost S3 class; retrieval in **12–48 hours**; min. 180-day storage charge
- **Use cases:** long-term regulatory retention, accessed 1–2×/year

### Storage Class Comparison Table

| Class | Storage Cost | Retrieval Fee | Access Speed | Min Storage | Best For |
|---|---|---|---|---|---|
| Standard | High | None | Instant | None | Frequent access |
| Intelligent-Tiering | Variable | None | Instant | None | Unknown patterns |
| Standard-IA | Medium | Per GB | Instant | 30 days | Monthly access |
| One Zone-IA | Lower | Per GB | Instant | 30 days | Re-creatable IA data |
| Glacier Instant | Low | Higher | Milliseconds | 90 days | Quarterly access |
| Glacier Flexible | Very Low | High | 1–12 hours | 90 days | Yearly access |
| Glacier Deep Archive | Lowest | Highest | 12–48 hours | 180 days | Rarely accessed |

> 💡 **Tip:** Use **S3 Lifecycle Policies** to auto-transition objects as they age — e.g. `Standard → Standard-IA (after 30 days) → Glacier (after 90 days)`.

## 4. Consolidated Cheat Sheet

```
S3 Bucket Names        → Globally unique (across ALL AWS accounts)
S3 Standard            → 3+ AZs by default (no config needed, unlike Azure ZRS)
S3 One Zone-IA         → Cheapest but single-AZ risk
S3 + CRR               → Cross-region DR, manual setup
Storage Class Ladder   → Standard → Intelligent-Tiering → Standard-IA →
                          One Zone-IA → Glacier Instant → Glacier Flexible →
                          Glacier Deep Archive
Lifecycle Policies     → Automate the class ladder based on object age
Block (EBS)            → EC2-only, intra-AZ, no built-in cross-AZ redundancy
Queue (SQS)            → Standard = throughput; FIFO = strict order
```
