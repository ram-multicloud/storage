## S3 Directory Buckets

### What it is
A **Directory Bucket** is the storage type used by **S3 Express One Zone**. Unlike general purpose buckets, objects are organized in a flat hierarchical namespace (like a real directory structure) within a single Availability Zone, giving single-digit millisecond latency.

Key points:
- Bucket name must end with a special suffix: `--azid--x-s3` (e.g. `--use1-az4--x-s3`)
- Data lives in one Availability Zone only (not replicated across AZs)
- Best for high-throughput, low-latency workloads (ML training, analytics staging, etc.)

### Create a Directory Bucket
```bash
aws s3api create-bucket \
  --bucket my-directory-bucket--use1-az4--x-s3 \
  --region us-east-1 \
  --create-bucket-configuration '{
    "Location": {"Type": "AvailabilityZone", "Name": "use1-az4"},
    "Bucket": {"Type": "Directory", "DataRedundancy": "SingleAvailabilityZone"}
  }'
```

### Upload a file
```bash
aws s3 cp sample.csv s3://my-directory-bucket--use1-az4--x-s3/data/sample.csv
```

or using the low-level API:
```bash
aws s3api put-object \
  --bucket my-directory-bucket--use1-az4--x-s3 \
  --key data/sample.csv \
  --body sample.csv
```

### Query / Read a file
List objects:
```bash
aws s3api list-objects-v2 \
  --bucket my-directory-bucket--use1-az4--x-s3 \
  --prefix data/
```

Download / read an object:
```bash
aws s3api get-object \
  --bucket my-directory-bucket--use1-az4--x-s3 \
  --key data/sample.csv \
  output.csv
```

## 2. S3 Table Buckets

### What it is
A **Table Bucket** is a purpose-built bucket type for **S3 Tables**, which stores data as **Apache Iceberg** tables. Instead of raw objects, you work with structured tables (namespaces + tables), queryable directly through engines like **Amazon Athena**, **Redshift**, **EMR**, or **Spark**.

Key points:
- Organized as: Table Bucket → Namespace → Table
- Data format: Apache Iceberg (columnar, transactional)
- Built-in automatic compaction and snapshot management
- You don't `put-object` raw files into a table — you insert/write structured records via a query engine

### Create a Table Bucket
```bash
aws s3tables create-table-bucket --name my-table-bucket
```

### Create a Namespace
```bash
aws s3tables create-namespace \
  --table-bucket-arn arn:aws:s3tables:us-east-1:123456789012:bucket/my-table-bucket \
  --namespace my_namespace
```

### Create a Table
```bash
aws s3tables create-table \
  --table-bucket-arn arn:aws:s3tables:us-east-1:123456789012:bucket/my-table-bucket \
  --namespace my_namespace \
  --name employees \
  --format ICEBERG
```

### "Upload" data (insert records via Athena)
1. In the Athena console/CLI, connect to the S3 Tables catalog (`s3tablescatalog`).
2. Define the table schema (if not already set) and insert data:

```sql
CREATE TABLE s3tablescatalog.my_namespace.employees (
  id int,
  name string,
  department string,
  salary double
)
LOCATION 's3://my-table-bucket/my_namespace/employees'
TBLPROPERTIES ('table_type' = 'ICEBERG');

INSERT INTO s3tablescatalog.my_namespace.employees
VALUES
  (1, 'Ravi', 'Engineering', 75000),
  (2, 'Anita', 'DevOps', 82000),
  (3, 'Karan', 'Support', 55000);
```

### Query the table
```sql
SELECT department, AVG(salary) AS avg_salary
FROM s3tablescatalog.my_namespace.employees
GROUP BY department;
```

Or via CLI (Athena start-query-execution):
```bash
aws athena start-query-execution \
  --query-string "SELECT * FROM my_namespace.employees" \
  --query-execution-context Database=my_namespace,Catalog=s3tablescatalog \
  --result-configuration OutputLocation=s3://my-athena-results-bucket/
```
