# AWS S3 Storage Classes

Amazon S3 offers multiple storage classes, each designed for a specific access pattern, availability level, and cost profile. Choosing the right class (or automating transitions with lifecycle rules) is key to controlling storage cost.

## Storage Classes

### 1. S3 Standard
- **Description:** Default, general-purpose storage class. High durability, availability, and performance.
- **Durability/Availability:** 99.999999999% (11 9's) durability, 99.99% availability.
- **Access:** Millisecond first-byte latency, no retrieval fee.
- **Use cases:** Websites, mobile/web apps, content distribution, gaming, big data analytics, frequently accessed data.

### 2. S3 Intelligent-Tiering
- **Description:** Automatically moves objects between access tiers (frequent, infrequent, archive) based on changing access patterns, with a small monitoring fee.
- **Access:** Millisecond latency for frequent/infrequent tiers; archive tiers behave like Glacier.
- **Use cases:** Data with unknown, changing, or unpredictable access patterns; long-lived datasets where you don't want to manage lifecycle rules manually.

### 3. S3 Standard-Infrequent Access (Standard-IA)
- **Description:** Lower storage cost than Standard, but with a per-GB retrieval fee. Same durability as Standard, multi-AZ.
- **Access:** Millisecond latency.
- **Use cases:** Backups, disaster recovery files, older data accessed occasionally (e.g., once a month).

### 4. S3 One Zone-Infrequent Access (One Zone-IA)
- **Description:** Like Standard-IA, but stored in a single Availability Zone instead of replicated across multiple AZs. Lower cost, lower resilience.
- **Access:** Millisecond latency.
- **Use cases:** Easily re-creatable data, secondary backup copies, or data that doesn't require multi-AZ resilience.

### 5. S3 Express One Zone
- **Description:** Purpose-built, high-performance storage class in a single AZ, designed for the fastest access speeds in S3 (single-digit millisecond latency).
- **Use cases:** Latency-sensitive applications, machine learning training/inference data, high-performance analytics workloads co-located with compute in the same AZ.

### 6. S3 Glacier Instant Retrieval
- **Description:** Archive storage with millisecond retrieval, at a lower cost than Standard-IA. Cheapest archive class with instant access.
- **Use cases:** Archive data accessed once a quarter, needing immediate retrieval (e.g., medical images, media assets).

### 7. S3 Glacier Flexible Retrieval
- **Description:** Low-cost archive storage with retrieval times ranging from minutes (expedited) to hours (standard/bulk).
- **Use cases:** Backup and disaster recovery archives, data accessed 1–2 times a year where retrieval delay of minutes-to-hours is acceptable.

### 8. S3 Glacier Deep Archive
- **Description:** Lowest-cost S3 storage class, designed for long-term retention. Retrieval takes up to 12 hours.
- **Use cases:** Regulatory/compliance archives, long-term data retention (7–10+ years), data rarely if ever accessed.

## Comparison Table

| Storage Class | Availability Zones | Retrieval Time | Min. Storage Duration | Typical Use Case |
|---|---|---|---|---|
| S3 Standard | Multi-AZ | Milliseconds | None | Active, frequently accessed data |
| S3 Intelligent-Tiering | Multi-AZ | Milliseconds (varies by tier) | None | Unpredictable access patterns |
| S3 Standard-IA | Multi-AZ | Milliseconds | 30 days | Infrequently accessed, backups |
| S3 One Zone-IA | Single AZ | Milliseconds | 30 days | Re-creatable, infrequent data |
| S3 Express One Zone | Single AZ | Single-digit milliseconds | None | Latency-sensitive, ML/analytics |
| S3 Glacier Instant Retrieval | Multi-AZ | Milliseconds | 90 days | Quarterly-access archives |
| S3 Glacier Flexible Retrieval | Multi-AZ | Minutes to hours | 90 days | Yearly-access archives, DR |
| S3 Glacier Deep Archive | Multi-AZ | Up to 12 hours | 180 days | Compliance, long-term retention |

## Lifecycle Management
S3 Lifecycle rules can automatically transition objects between classes based on object age, reducing storage cost without manual intervention.

Example lifecycle policy:
```json
{
  "Rules": [
    {
      "Id": "CostOptimization",
      "Status": "Enabled",
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER_IR" },
        { "Days": 365, "StorageClass": "DEEP_ARCHIVE" }
      ]
    }
  ]
}
```
